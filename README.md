## Описание проекта

### Постановка задачи

Проект посвящён задаче восстановления трёхмерной структуры сцены и определения поз камер по набору изображений в условиях, приближенных к реальным. Это классическая задача Structure-from-Motion (SfM), которая лежит в основе фотограмметрии, автономной навигации, робототехники, AR/VR и картографии.

Реальные данные «грязные»: изображения сделаны разными камерами, содержат выбросы, дубликаты, размытые кадры и не всегда относятся к одной сцене.

За основу взято соревнование **[Image Matching Challenge 2025](https://www.kaggle.com/competitions/image-matching-challenge-2025)**. Пайплайн решает три ключевые задачи:

1. **Кластеризация сцен:** разбить неупорядоченный набор изображений на кластеры, соответствующие отдельным сценам.
1. **Фильтрация выбросов:** определить изображения-выбросы, не относящиеся ни к одной сцене.
1. **Оценка поз камер:** для каждой найденной сцены восстановить позы камер — матрицу поворота и вектор переноса.

**Зачем это нужно (прикладная ценность):** подобные алгоритмы используются в картографических сервисах (Яндекс Карты, 2ГИС), автономных автомобилях, БПЛА/дронах, складских роботах, оцифровке объектов культурного наследия и AR-навигации.

### Пайплайн: модель + геометрия

Две независимые системы, каждая делает своё:

1. **Эмбеддинги и группировка.** Дообученная [DINOv2](https://github.com/facebookresearch/dinov2) (`src/sfm_rotations/model.py`) превращает каждую картинку в вектор-дескриптор; эмбеддинги кластеризуются агломеративным методом по косинусному расстоянию внутри каждого датасета (`src/sfm_rotations/metrics.py`).
1. **Позы камер.** Внутри кластера пары картинок отбираются по сходству эмбеддингов, матчатся локальными признаками ([ALIKED](https://github.com/ShaohuaLong/ALIKED) + [LightGlue](https://github.com/cvg/LightGlue)), матчи проверяются геометрически, и инкрементальный маппер [COLMAP](https://colmap.github.io/) (`pycolmap`) восстанавливает позы (`src/sfm_rotations/geometry.py`). Незарегистрированные картинки остаются в кластере с позой `nan`.

Нейросеть позы не предсказывает: world-системы координат сцен произвольны, absolute pose regression на них не генерализуется — поэтому позы считает геометрия.

### Метрики

Главной целевой метрикой соревнования Image Matching Challenge является **`imc/score`** — гармоническое среднее (аналог F1-меры), объединяющее качество группировки кадров и точность восстановления 3D-поз:

> **Score = 2 · (mAA · Clustering) / (mAA + Clustering)**

- **`imc/clustering`** (аналог Precision) — качество кластеризации: доля корректно отнесённых к своим сценам изображений и точность фильтрации посторонних кадров (выбросов).
- **`imc/mAA`** (*mean Average Accuracy*, аналог Recall) — геометрическая точность: средняя доля успешно зарегистрированных камер, чьи восстановленные пространственные позы укладываются в заданные пороги погрешности.

Именно по метрике `imc/score` на валидационном сплите автоматически выбирается лучший чекпоинт (`best.pt`). Протокол оценки заморожен в `contracts/protocol.yaml` (версия 3) и покрыт контрактными тестами `tests/contracts/`.

# Технические детали работы с проектом

## Setup

Пошаговая настройка окружения с нуля (Python 3.10):

```bash
# 1. Установить uv
wget -qO- https://astral.sh/uv/install.sh | sh
# перезапустить терминал (или ввести команду, которую предложит установщик)

# 2. Создать окружение и установить зависимости (из корня репозитория)
uv venv --python 3.10
source .venv/bin/activate
uv sync --all-groups

# 3. Установить git-хуки качества кода
pre-commit install

# 4. Настроить доступ к DVC-хранилищу данных и весов (см. «Data management»)
ssh-keygen -t rsa -b 4096 -f ~/.ssh/mlops   # публичный ключ — админам группы
dvc remote modify --local sfm-dvc keyfile ~/.ssh/mlops

# 5. Скачать данные и веса
dvc pull

# 6. (Только для обучения) доступ к MLflow-серверу
cp .env.example .env   # вписать MLFLOW_TRACKING_USERNAME / MLFLOW_TRACKING_PASSWORD
```

После этого доступны: обучение (`python -m sfm_rotations.train`), инференс соревнования (`python -m sfm_rotations.infer`) и CLI `reconstruct`.

## Train

Конфигурация обучения управляется **[Hydra](https://hydra.cc/)**: дефолты в [configs/train/main.yaml](configs/train/main.yaml), переопределение — аргументами командной строки. Данные подтягиваются из DVC автоматически (`pull_train_data`).

```bash
# 1. Запуск с параметрами по умолчанию из configs/train/main.yaml:
python -m sfm_rotations.train

# 2. Запуск БЕЗ логирования в MLflow (для тестов и отладки пайплайна):
python -m sfm_rotations.train --no-logging

# 3. Переопределение любых параметров через аргументы командной строки:
python -m sfm_rotations.train epochs=5 lr=1e-4 batch_size=21

# 4. Переопределение списков и путей:
python -m sfm_rotations.train data_root=data checkpoints=checkpoints/exp1 "loss_weights=[1.0,0.0,0.0]"

# 5. Просмотр полной справки и доступных параметров:
python -m sfm_rotations.train --help
```

Что происходит: DINOv2 дообучается supervised contrastive loss на train-сплите (батч-сэмплер собирает батчи из нескольких сцен + outliers), после каждой эпохи считается `imc/score` на замороженном val-сплите, лучшие веса пишутся в `checkpoints/<run>/best.pt`.

## Infer

### Данные: формат и пример

Вход — папка с изображениями (`.png`/`.jpg`/`.jpeg`) в layout соревнования:

```
data/test/            # пример лежит в DVC: dvc pull data/test.dvc
- stairs/             # датасет = подпапка
  - *.png
- ETs/
  - *.png
```

Датасет — группа сцен, кластеризация работает строго внутри него. Одиночная папка с картинками трактуется как один датасет с именем папки.

### Hydra-скрипт (пайплайн соревнования)

```bash
# 1. Запуск с параметрами по умолчанию (configs/inference/fast.yaml на основе main.yaml):
python -m sfm_rotations.infer

# 2. Запуск в режиме максимального качества (configs/inference/quality.yaml):
python -m sfm_rotations.infer --config-name=quality

# 3. Запуск на отдельной сцене (например, только stairs):
python -m sfm_rotations.infer test_dir=data/test/stairs

# 4. Запуск на нескольких сценах одновременно (общая папка data/test):
python -m sfm_rotations.infer test_dir=data/test

# 5. Запуск с автоматическим скачиванием данных через DVC (--dvc-pull):
python -m sfm_rotations.infer --dvc-pull

# 6. Указание своего чекпоинта и пути сохранения:
python -m sfm_rotations.infer checkpoint=checkpoints/dinov2-large/best.pt output_path=predictions.csv
```

Скрипт автоматически определяет структуру `test_dir`: папка с поддиректориями обрабатывается раздельно по сценам (эмбеддинги, кластеризация и реконструкция работают независимо, исключая смешивание сцен и снижая пиковую память); конкретная папка со снимками — как одна сцена.

Выход — **отдельный CSV на сцену** с суффиксом `_<scene_name>` в папке с временной меткой (`results/YYYY-MM-DD_HH-MM-SS/`, настраивается `output_path`):

| Колонка              | Значение                                                      |
| -------------------- | ------------------------------------------------------------- |
| `dataset`            | название сцены/датасета (`ETs`, `stairs`)                     |
| `scene`              | предсказанный кластер (`cluster0`, `cluster1` или `outliers`) |
| `image`              | относительное имя файла изображения                           |
| `rotation_matrix`    | матрица поворота 3x3 через `;` (row-major)                    |
| `translation_vector` | вектор перемещения 3D через `;`                               |

> **Что означает `nan` в позах:** если COLMAP не смог надёжно восстановить позу кадра (смаз, отсутствие текстур, экстремальный ракурс), в `rotation_matrix` и `translation_vector` записываются `nan`. Это официальный стандарт Image Matching Challenge: кадр остаётся привязанным к своему кластеру, а отсутствие позы сигнализирует проверяющей системе о незарегистрированной камере.

### CLI reconstruct (разовые прогоны на своей папке)

Консольная утилита (на [click](https://click.palletsprojects.com/)): на вход — путь к папке с фотографиями, на выход — строго валидный JSON с найденными сценами и позами камер. Пользователь передаёт только пути; архитектура модели и пороги кластеризации берутся из самого чекпоинта (`model_config`/`postprocess`), как в hydra-инференсе, остальное — из дефолтов CLI.

#### Быстрый старт

```bash
uv sync --all-groups && source .venv/bin/activate
dvc pull checkpoints/dinov2-large.dvc    # веса модели, см. «Data management»

reconstruct --input-dir data/test --output result.json \
    --checkpoint checkpoints/dinov2-large/best.pt --num-threads 1
```

Прервали прогон (Ctrl+C)? Повторите ту же команду с `--resume` — продолжит с последнего сохранённого этапа, а не с нуля.

#### Как это работает (и зачем нужны флаги)

Флаги сгруппированы по ролям: **вход-выход** (меняют что и куда), **прерывание** (кэш), **скорость** (на результат НЕ влияют), **качество** (влияют на результат).

1. **Поиск данных.** Подпапки `--input-dir` = датасеты (layout `data/test`); картинки в корне = один датасет с именем папки. `--input-dir` можно повторять для нескольких папок.
1. **Эмбеддинги.** Дообученная DINOv2 (веса из `--checkpoint`) превращает каждую картинку в вектор: фото одной сцены оказываются близки, разных — далеки. Это «мозг» группировки; он ничего про 3D не знает.
1. **Кластеризация.** Внутри каждого датасета картинки склеиваются в сцены по косинусному расстоянию до порога (из чекпоинта, переопределяется `--cluster-distance`); группы меньше `--min-cluster-size` помечаются `outliers` (фото из неизвестной/уникальной сцены).
1. **Позы камер.** Внутри сцены пары картинок матчатся локальными признаками (ALIKED + LightGlue), и COLMAP по этим матчам вычисляет, откуда снималась каждая фотография (`rotation_matrix`, `translation_vector`). Система координат у каждой сцены своя, произвольная.
1. **JSON.** Результат валидируется контрактом (`pipeline.validate_result`) и атомарно пишется в `--output`.

Каждый этап (2–4) сохраняет результат в кэш `--cache-dir` (по умолчанию `<output>.cache`), и `--resume` дочитывает готовые этапы с диска. Дешёвые этапы (эмбеддинги, кластеры) кэшируются целиком, дорогой этап поз — по одному файлу на кластер: упал/прервался один кластер — остальные готовы.

#### Формат результата

```json
{
  "schema_version": 1,
  "pipeline_version": "0.0.1",
  "meta": {"device": "cpu", "checkpoint": "...", "params": {...}, "errors": []},
  "datasets": [
    {
      "name": "ds_a",
      "num_images": 5,
      "num_clusters": 2,
      "num_outliers": 1,
      "num_registered": 4,
      "images": [
        {
          "image": "ds_a/photo1.png",
          "scene": "cluster0",
          "rotation_matrix": [[0.85, -0.39, 0.36], [0.47, 0.87, -0.18], [-0.24, 0.32, 0.92]],
          "translation_vector": [-1.17, -1.05, 2.46]
        },
        {
          "image": "ds_a/photoX.png",
          "scene": "outliers",
          "rotation_matrix": null,
          "translation_vector": null
        }
      ]
    }
  ]
}
```

- `image` — путь относительно `--input-dir`; `scene` — `clusterN` или `outliers`;
- `rotation_matrix` (3×3) и `translation_vector` (3) — поза камеры; `null` — картинка не зарегистрирована COLMAP’ом (или это выброс). Центр камеры: `c = -Rᵀt`;
- `meta.errors` — если геометрия упала на отдельном кластере, прогон продолжается, позы этого кластера остаются `null`, а причина попадает сюда;
- JSON проходит `validate_result` до записи — битый файл появиться не может.

| `--device cuda\|cpu`            | cuda если есть                 | скорость   | на чём считать; на CPU всё работает, но медленно                                                                                                                                  |
| `--batch-size`, `--num-workers` | 32, 0                          | скорость   | только пропускная способность эмбеддингов; на результат не влияют                                                                                                                 |
| `--num-threads N`               | -1 (все)                       | скорость   | потоки COLMAP-маппера. **На macOS (arm64) ставьте 1** — в многопотоке pycolmap падает с SIGSEGV                                                                                   |
| `--cluster-distance D`          | из чекпоинта                   | качество   | порог похожести при склейке в сцены: 0 = «те же пиксели», 2 = «максимально разные». Меньше — строже делит (больше раздробленных сцен и outliers), больше — склеивает разные сцены |
| `--min-cluster-size N`          | из чекпоинта                   | качество   | группы из \<N картинок объявляются `outliers` (защита от склейки двух случайных фото)                                                                                             |
| `--linkage L`                   | из чекпоинта                   | качество   | связывание агломеративной кластеризации: `single` (цепочки перекрытий), `average`, `complete`                                                                                     |
| `--neighbors N`                 | 20                             | качество   | сколько ближайших по эмбеддингу картинок матчить на каждую. Меньше — быстрее; больше — выше шанс зарегистрировать слабые фото                                                     |
| `--max-keypoints N`             | 2048                           | качество   | максимум ключевых точек ALIKED на картинку (текстурированные сцены — можно больше)                                                                                                |
| `--resize N`                    | 1024                           | качество   | длинная сторона при извлечении фич: больше — точнее матчи, медленнее и больше памяти                                                                                              |
| `--min-matches N`               | 15                             | качество   | минимальное число матчей в паре, иначе пара не участвует в реконструкции. Меньше — смелнее, больше — надёжнее                                                                     |

**Когда что крутить:**

- много `outliers`, хотя сцена одна → `--cluster-distance` больше (например 0.4) или модель хуже работает на таких фото;
- разные сцены склеились в один `clusterN` → `--cluster-distance` меньше;
- много картинок в сцене с `null`-позой → `--neighbors` больше, `--min-matches` меньше;
- матчинг медленный на больших группах → `--neighbors` меньше, `--resize` меньше.

#### Коды выхода

| Код | Значение                                                                            |
| --- | ----------------------------------------------------------------------------------- |
| 0   | успех (отдельные упавшие кластеры — в `meta.errors`, позы там `null`)               |
| 2   | ошибка использования: нет папки/картинок/чекпоинта, кэш не соответствует `--resume` |
| 130 | Ctrl+C: прогресс в кэше, продолжайте с `--resume`                                   |
| 1   | непредвиденная ошибка                                                               |
