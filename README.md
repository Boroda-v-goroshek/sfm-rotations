## Описание проекта

### Постановка задачи

Проект посвящён задаче восстановления трёхмерной структуры сцены и определения поз камер по набору изображений в условиях, приближенных к реальным. Это классическая задача Structure-from-Motion (SfM), которая лежит в основе фотограмметрии, автономной навигации, робототехники, AR/VR и картографии.

Реальные данные «грязные»: изображения сделаны разными камерами, содержат выбросы, дубликаты, размытые кадры и не всегда относятся к одной сцене.

За основу взято соревнование **[Image Matching Challenge 2025](https://www.kaggle.com/competitions/image-matching-challenge-2025)**. Пайплайн решает три ключевые задачи:

1. **Кластеризация сцен:** разбить неупорядоченный набор изображений на кластеры, соответствующие отдельным сценам.
1. **Фильтрация выбросов:** определить изображения-выбросы, не относящиеся ни к одной сцене.
1. **Оценка поз камер:** для каждой найденной сцены восстановить позы камер — матрицу поворота и вектор переноса.

**Зачем это нужно (прикладная ценность):** подобные алгоритмы используются в картографических сервисах (Яндекс Карты, 2ГИС), автономных автомобилях, БПЛА/дронах, складских роботах, оцифровке объектов культурного наследия и AR-навигации.

## Инференс (Infer)

> Для разовых прогонов на своей папке фотографий используйте [CLI reconstruct](#cli-reconstruct) —
> он делает то же самое, принимает пути в аргументах, кэширует этапы и отдаёт JSON.
> Секция ниже — про hydra-скрипт для пайплайна соревнования (submission.csv для val-сплита).

Модель отвечает только за группировку картинок, а позы считает геометрия ([geometry.py](src/sfm_rotations/geometry.py)):

1. DINOv2-эмбеддинги кластеризуются внутри каждого датасета / сцены.
1. Внутри кластера пары картинок отбираются по сходству эмбеддингов (`geometry.neighbors`).
1. На парах работают ALIKED и LightGlue, матчи проверяются геометрически.
1. Инкрементальный маппер COLMAP восстанавливает позы. Незарегистрированные картинки остаются в кластере с позой `nan`.

При запуске автоматически подтягиваются тестовые данные через **DVC API** (файл `data/test.dvc`).

### Запуск инференса:

```bash
# 1. Запуск с параметрами по умолчанию (configs/inference/fast.yaml на основе main.yaml):
python -m sfm_rotations.infer

# 2. Запуск в режиме максимального качества (configs/inference/quality.yaml):
python -m sfm_rotations.infer --config-name=quality

# 3. Запуск на отдельной сцене (например, только stairs):
python -m sfm_rotations.infer test_dir=data/test/stairs

# 4. Запуск на нескольких сценах одновременно (общая папка data/test):
python -m sfm_rotations.infer test_dir=data/test

# 5. Запуск с автоматическим скачиванием данных через DVC (--dvc-pull):
python -m sfm_rotations.infer --dvc-pull

# 6. Указание своего чекпоинта и пути сохранения:
python -m sfm_rotations.infer checkpoint=checkpoints/dinov2-large/best.pt output_path=predictions.csv
```

### Раздельный инференс и сохранение результатов

Скрипт инференса автоматически определяет структуру входной директории `test_dir`:

- **Поддержка одиночной сцены и набора сцен:**

  - Если передана папка с поддиректориями (например, `data/test`, где лежат `ETs/` и `stairs/`), инференс выполняется раздельно для каждой сцены: эмбеддинги, кластеризация и 3D-реконструкция COLMAP работают независимо по очереди, исключая смешивание разных сцен и снижая пиковое потребление памяти.
  - Если передана конкретная папка со снимками сцены (например, `data/test/stairs`), обрабатывается только она.

- **Именование и структура выходных файлов:**

  - Результаты автоматически сохраняются в папку с временной меткой: `results/YYYY-MM-DD_HH-MM-SS/` (настраивается в конфиге Hydra через `output_path: results/${now:%Y-%m-%d_%H-%M-%S}/...`).
  - **Для каждой сцены создаётся свой отдельный CSV-файл** с суффиксом `_<scene_name>`: например, `dinov2-large_ETs.csv` и `dinov2-large_stairs.csv` (общий объединённый файл не создаётся).

Каждый CSV-файл содержит колонки:

- `dataset`: название сцены / датасета (`ETs`, `stairs`);
- `scene`: предсказанный кластер сцены (`cluster0`, `cluster1` или `outliers`);
- `image`: относительное имя файла изображения;
- `rotation_matrix`: матрица поворота камеры (3x3, записанная через `;` в row-major порядке);
- `translation_vector`: вектор перемещения (3D, через `;`).

> **Что означает `nan` в позах:**
> Если для конкретного кадра COLMAP не смог надёжно восстановить 3D-позу (из-за смаза, недостатка текстур или экстремального ракурса), в `rotation_matrix` и `translation_vector` записываются значения `nan`. Это официальный стандарт Image Matching Challenge: кадр остаётся привязанным к своему кластеру, а отсутствие позы сигнализирует проверяющей системе о незарегистрированной камере.

## CLI reconstruct

Консольная утилита: на вход — путь к папке с фотографиями, на выход — строго валидный JSON
с найденными сценами и позами камер. Пользователь передаёт только пути; архитектура модели
и пороги кластеризации берутся из самого чекпоинта (`model_config`/`postprocess`), как в
hydra-инференсе, остальное — из дефолтов CLI.

### Быстрый старт

```bash
uv sync --all-groups && source .venv/bin/activate
dvc pull checkpoints/dinov2-large.dvc    # веса модели, см. «Работа с DVC»

reconstruct --input-dir data/test --output result.json \
    --checkpoint checkpoints/dinov2-large/best.pt --num-threads 1
```

Прервали прогон (Ctrl+C)? Повторите ту же команду с `--resume` — продолжит с последнего
сохранённого этапа, а не с нуля.

### Как это работает (и зачем нужны флаги)

Дальше флаги сгруппированы по ролям: **вход-выход** (меняют что и куда), **прерывание** (кэш),
**скорость** (на результат НЕ влияют), **качество** (влияют на результат).

1. **Поиск данных.** Подпапки `--input-dir` = датасеты (layout `data/test`); картинки в корне
   = один датасет с именем папки. `--input-dir` можно повторять для нескольких папок.
1. **Эмбеддинги.** Дообученная DINOv2 (веса из `--checkpoint`) превращает каждую картинку
   в вектор: фото одной сцены оказываются близки, разных — далеки. Это «мозг»
   группировки; он ничего про 3D не знает.
1. **Кластеризация.** Внутри каждого датасета картинки склеиваются в сцены по косинусному
   расстоянию до порога (из чекпоинта, переопределяется `--cluster-distance`); группы меньше
   `--min-cluster-size` помечаются `outliers` (фото из неизвестной/уникальной сцены).
1. **Позы камер.** Вторая «система» — геометрия: внутри сцены пары картинок матчатся
   локальными признаками (ALIKED + LightGlue), и COLMAP по этим матчам вычисляет, откуда
   снималась каждая фотография (`rotation_matrix`, `translation_vector`). Система координат
   у каждой сцены своя, произвольная.
1. **JSON.** Результат валидируется контрактом (`pipeline.validate_result`) и атомарно
   пишется в `--output`.

Каждый этап (2–4) сохраняет результат в кэш `--cache-dir` (по умолчанию `<output>.cache`),
и `--resume` дочитывает готовые этапы с диска. Дешёвые этапы (эмбеддинги, кластеры)
кэшируются целиком, дорогой этап поз — по одному файлу на кластер: упал/прервался один
кластер — остальные готовы.

### Формат результата

```json
{
  "schema_version": 1,
  "pipeline_version": "0.0.1",
  "meta": {"device": "cpu", "checkpoint": "...", "params": {...}, "errors": []},
  "datasets": [
    {
      "name": "ds_a",
      "num_images": 5,
      "num_clusters": 2,
      "num_outliers": 1,
      "num_registered": 4,
      "images": [
        {
          "image": "ds_a/photo1.png",
          "scene": "cluster0",
          "rotation_matrix": [[0.85, -0.39, 0.36], [0.47, 0.87, -0.18], [-0.24, 0.32, 0.92]],
          "translation_vector": [-1.17, -1.05, 2.46]
        },
        {
          "image": "ds_a/photoX.png",
          "scene": "outliers",
          "rotation_matrix": null,
          "translation_vector": null
        }
      ]
    }
  ]
}
```

- `image` — путь относительно `--input-dir`; `scene` — `clusterN` или `outliers`;
- `rotation_matrix` (3×3) и `translation_vector` (3) — поза камеры; `null` — картинка не
  зарегистрирована COLMAP’ом (или это выброс). Центр камеры: `c = -Rᵀt`;
- `meta.errors` — если геометрия упала на отдельном кластере, прогон продолжается, позы
  этого кластера остаются `null`, а причина попадает сюда;
- JSON проходит `validate_result` до записи — битый файл появиться не может.

### Флаги

| Флаг                            | По умолчанию                   | Группа     | Зачем                                                                                                                                                                             |
| ------------------------------- | ------------------------------ | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--input-dir DIR`               | — (обязательный, ×N)           | вход       | папка с фотографиями; подпапки = датасеты, картинки в корне = один датасет                                                                                                        |
| `--output FILE`                 | — (обязательный)               | вход       | куда записать итоговый JSON                                                                                                                                                       |
| `--output-csv FILE`             | нет                            | вход       | дополнительно записать submission.csv в формате соревнования (те же данные, что в JSON)                                                                                           |
| `--resume`                      | выкл                           | прерывание | продолжить с последнего этапа из кэша; при несовпадении входа/параметров с кэшем — ошибка (а не тихий пересчёт)                                                                   |
| `--cache-dir DIR`               | `<output>.cache`               | прерывание | папка промежуточных результатов: `embeddings.npz`, `clusters.json`, `cluster-*.json`, `fingerprint.json`                                                                          |
| `--config YAML`                 | нет                            | прочее     | опциональный yaml с дефолтами geometry/batch; параметры модели и кластеризации берутся из чекпоинта                                                                               |
| `--checkpoint PT`               | `checkpoints/baseline/best.pt` | прочее     | веса дообученной DINOv2 (`dvc pull checkpoints/dinov2-large.dvc`); из него же — backbone и пороги кластеризации                                                                   |
| `-v`, `--verbose`               | INFO-лог                       | прочее     | DEBUG-логи каждого этапа; логи идут в stderr, JSON — только в файл                                                                                                                |
| `--version`                     |                                | прочее     | версия CLI                                                                                                                                                                        |
| `--device cuda\|cpu`            | cuda если есть                 | скорость   | на чём считать; на CPU всё работает, но медленно                                                                                                                                  |
| `--batch-size`, `--num-workers` | 32, 0                          | скорость   | только пропускная способность эмбеддингов; на результат не влияют                                                                                                                 |
| `--num-threads N`               | -1 (все)                       | скорость   | потоки COLMAP-маппера. **На macOS (arm64) ставьте 1** — в многопотоке pycolmap падает с SIGSEGV                                                                                   |
| `--cluster-distance D`          | из чекпоинта                   | качество   | порог похожести при склейке в сцены: 0 = «те же пиксели», 2 = «максимально разные». Меньше — строже делит (больше раздробленных сцен и outliers), больше — склеивает разные сцены |
| `--min-cluster-size N`          | из чекпоинта                   | качество   | группы из \<N картинок объявляются `outliers` (защита от склейки двух случайных фото)                                                                                             |
| `--linkage L`                   | из чекпоинта                   | качество   | связывание агломеративной кластеризации: `single` (цепочки перекрытий), `average`, `complete`                                                                                     |
| `--neighbors N`                 | 20                             | качество   | сколько ближайших по эмбеддингу картинок матчить на каждую. Меньше — быстрее; больше — выше шанс зарегистрировать слабые фото                                                     |
| `--max-keypoints N`             | 2048                           | качество   | максимум ключевых точек ALIKED на картинку (текстурированные сцены — можно больше)                                                                                                |
| `--resize N`                    | 1024                           | качество   | длинная сторона при извлечении фич: больше — точнее матчи, медленнее и больше памяти                                                                                              |
| `--min-matches N`               | 15                             | качество   | минимальное число матчей в паре, иначе пара не участвует в реконструкции. Меньше — смелнее, больше — надёжнее                                                                     |

**Когда что крутить:**

- много `outliers`, хотя сцена одна → `--cluster-distance` больше (например 0.4) или модель хуже работает на таких фото;
- разные сцены склеились в один `clusterN` → `--cluster-distance` меньше;
- много картинок в сцене с `null`-позой → `--neighbors` больше, `--min-matches` меньше;
- матчинг медленный на больших группах → `--neighbors` меньше, `--resize` меньше.

### Коды выхода

| Код | Значение                                                                            |
| --- | ----------------------------------------------------------------------------------- |
| 0   | успех (отдельные упавшие кластеры — в `meta.errors`, позы там `null`)               |
| 2   | ошибка использования: нет папки/картинок/чекпоинта, кэш не соответствует `--resume` |
| 130 | Ctrl+C: прогресс в кэше, продолжайте с `--resume`                                   |
| 1   | непредвиденная ошибка                                                               |

## Метрики

Главной целевой метрикой соревнования Image Matching Challenge является **`imc/score`** — гармоническое среднее (аналог F1-меры), объединяющее качество группировки кадров и точность восстановления 3D-поз:

> **Score = 2 · (mAA · Clustering) / (mAA + Clustering)**

- **`imc/clustering`** (аналог Precision) — качество кластеризации: доля корректно отнесённых к своим сценам изображений и точность фильтрации посторонних кадров (выбросов).
- **`imc/mAA`** (*mean Average Accuracy*, аналог Recall) — геометрическая точность: средняя доля успешно зарегистрированных камер, чьи восстановленные пространственные позы укладываются в заданные пороги погрешности.

Именно по метрике `imc/score` на валидационном сплите автоматически выбирается лучший чекпоинт (`best.pt`).

# 2. Оценка в режиме максимального качества (configs/evaluate/quality.yaml):
